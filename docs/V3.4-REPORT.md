## Phase 0 — contract split (done)

The forbidden list is two lists (design-spec §6, theme-contract doc).
Contract additions: `elevation` +softShadow/clay/halo/gloss with
`elevationParams`; `meter` +ticks/ring/dial/blob; `shape.tilt` (≤2°, 0 with

`domainGroundOn` pairs; optional `surfaces.gradient`. New conformance:
ground pairs ≥4.5:1, gradients carry every text colour at both ends,
ring/dial themes must state over-cap in words (asserted on fat 41/36 via
capState/overCapSuffix — the same functions the components render with),
tilt caps. The six original themes declare none of the new tokens; pill/
tilt were added as inert values.

miniature Today — the real Card/KV/HeroNumeral/HeroRings/HeroDial/
MacroRow/CapRow/SegmentedStack components inside a nested ThemeProvider
at 0.19 scale, pointerEvents none, 304×620 frame. Previews use the

accent border + #3E9B78 tick + "X selected · Confirm" bar; nothing
restyles until Confirm; back or tapping the current/staged row clears.
Every row is a button with a full a11y label; the bar announces via
accessibilityLiveRegion. The Settings Appearance chip-list is replaced
by a receipt row → full-screen modal. Onboarding gains step 9 (of 9):
the same ThemePickerList with sample data; the picked theme rides
`buildProfile` so "Build my targets" is the confirm; skipping keeps
Minimal.

The preview's per-theme branching lives in a pure `previewPlan()`
(model, tested for all 11 themes: never throws, fractions clamp,
over-cap stays in words on ring, dial and numeral variants — the

## Phase 3 — Pebble (suite 1040 → 1056 green)

The mascot that survives the app's own honesty rules, because the rules
are code, not copy:

- **The slot law.** `packages/ui/src/pebble/Pebble.tsx` holds the SVG
  (path verbatim from `docs/basalt-picker.html`; two expressions only,
  neutral and a timed blink) and `PebbleSlot({ proposal })`, which
  returns null when `proposal` is null. There is no free-text prop —
  the only way to make Pebble speak is a `PebbleProposal`, and every
  proposal carries exactly two actions, one of which is always the way
  out (model-tested).
- **Proposals from engines, never commentary.** Four builders in
  `app/src/lib/pebbleModel.ts`: progression (from `suggestNext`
  numbers), macro shortfall (protein ≥25 g short, non-empty day,
  15:00–21:00), readiness swap (score <62 with a session today),
  sleep debt (≥90 min under the sleep target). Each returns null
  without a real engine value; macro proposals stay silent under
  Hide-the-numbers. Dismissals are per-proposal, per-day.
- **Three toggles, off by default** (Settings › Pebble): Show Pebble
  in the app; Notifications come from Pebble (disabled until the first
  is on — normalization enforces the dependency in the model too);
  Pebble on Trends and data screens (default off even when Pebble is
  on). Empty states and errors are NEVER, regardless of settings —
  `pebbleAllowedOnSurface` is pinned by test across every surface ×
  settings combination.
- **The voice law.** `voicedContent` can change title and icon and
  nothing else, by construction. Week in Review, the monthly report
  and the vitals-deviation alert all schedule through it; flipping the
  toggle re-issues anything already scheduled under the new voice
  (`pebbleRevoice.ts`, triggers rebuilt from the same models the
  schedulers use). `allNotifContents` walks every notification Basalt
  can schedule and the parity test pins the on/off sets identical
  apart from title/icon — there is no notification that exists only
  because Pebble is on.
- Honest limitation: expo-notifications has no per-notification
  Android large-icon API, so the pebble icon rides `data.icon` for a
  future notifee/config-plugin pass; today the visible Android
  difference is the title. The model already carries the icon field
  and the test pins it.
