# V3.4 report — five expressive themes, live theme picker, Pebble

Branch `v3-4-themes`. Baseline before Phase 0: **871 tests green**.

## Phase 0 — contract split (done)

The forbidden list is two lists (design-spec §6, theme-contract doc).
Contract additions: `elevation` +softShadow/clay/halo/gloss with
`elevationParams`; `meter` +ticks/ring/dial/blob; `shape.tilt` (≤2°, 0 with
a mono data face) and `radius.pill`; optional `fill.domainGround`/
`domainGroundOn` pairs; optional `surfaces.gradient`. New conformance:
ground pairs ≥4.5:1, gradients carry every text colour at both ends,
ring/dial themes must state over-cap in words (asserted on fat 41/36 via
capState/overCapSuffix — the same functions the components render with),
tilt caps. The six original themes declare none of the new tokens; pill/
tilt were added as inert values.

## Phase 1 — five themes (done; suite 871 → 1006 green)

Clay, Sticker, Gummy, Soft, Candy Rings per the mockups, wired into the
registry, switcher and the profile type; the DB theme CHECK constraint was
widened by migration `20260904103000_basalt_theme_check_v34.sql` (found the
hard way: chip taps silently no-oped until the constraint let the save in).
Rendering is token-driven throughout — no theme id ever branches a
component: Card/Tile read the new elevations + tilt + lead gradient +
domain grounds; the Today hero switches numeral/rings/dial on
`shape.meter`; fat never rings (words, conformance-enforced). Typefaces
load lazily per theme (`app/src/lib/expressiveFonts.ts`) — Minimal's
startup registers nothing new; the assets still ship in the binary because
RN cannot code-split, which is the honest limit of "not in the startup
bundle".
