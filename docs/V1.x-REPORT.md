## 1 · ai-quick-add model A/B — Sonnet 5 is now the default

A 20-case test set (item-count band, generous kcal range, portion-note and meal-hint checks) ran
live through the deployed Edge Function against all three candidates:

| Model | Passed | Median | p90 | Notable misses |
|---|---|---|---|---|
| `claude-sonnet-5` | **20/20** | 4.0 s | 5.1 s | none |
| `claude-opus-4-8` | 18/20 | 5.2 s | 10.2 s | two borderline range edges (410 vs cap 400; 1420 vs cap 1400) |
| `claude-haiku-4-5` | 15/20 | 2.7 s | 6.1 s | Tim Tam estimated 3× over; smoothie split into 3 items; flat white 240 kcal |

Quality held on Sonnet 5 (equal-or-better than Opus on this set) at lower cost and latency, so it
became the default. Haiku did not hold — its misses are the kind the honesty rules exist to
prevent. The whitelisted `model` override stays for future evals; the numbers live in the
function's header comment. Reproduce with a fresh throwaway account via the harness pattern in
this batch's commit.

## 2 · Outdoor map tile

Pure builders in `@basalt/training` (`route-map.ts`, 12 tests): route + endpoint GeoJSON, a
deterministic Web-Mercator camera fit (no map-ref timing), and the complete MapLibre style JSON —
dark OSM-data raster over a bg-colored background layer, single carbs-accent route line, hollow
start / filled end circle markers, per the prototype's map treatment. `WalkMap` is a thin static
shell (all gestures off, scale bar on) rendered on the walk-saved summary and expandable per
recent walk. Attribution appears as both the MapLibre ornament and a srcnote naming OSM/CARTO and
that the route comes from the device GPS only.

## 3 · V1.x list, in the report's order

- **Planned vs eaten** — `reconcilePlan` (pure, 10 tests): recipe in its slot = *as planned*;
  in another slot = *eaten · different slot*; other food in the slot = *something else logged*
  (a swap, not a fault); past empty slot = *not logged*; today stays *pending* until it's over.
  A same-named manual entry doesn't pass for the planned recipe. No outcome text scolds — pinned
  by test. Trailing-7-days card on the Planner.
- **Week in Review notification** — opt-in from Settings, Sunday 18:00, default off. A local
  weekly trigger runs no JS at delivery, so the notification is honestly a fixed prompt
  ("Written from your data — open Trends to read it") — never numbers. Trigger shape, stable
  identifier, and no-cheerleading copy all pinned by tests. Tap routes to Trends, cold start
  included.
- **Guided timer survives screen-off** — two defensive layers: (1) wall-clock catch-up in the
  pure engine (`tickMany` replays missed seconds — sets that completed during a gap still
  auto-log; `collapseSensory` fires the motor once per batch); the store now measures real
  elapsed time instead of counting interval fires. (2) A notifee foreground service whose one
  job is process priority, with a silent ongoing notification updated only on phase change.
  Android 14 typed-service declaration via `app/plugins/withTimerFgs.js`. Failure is honest:
  if the service can't start, the srcnote says the timer only runs with the app open.
- **Condition-based library biasing** — only mechanical load conditions (shoulder, knee,
  lower back, limited mobility) reorder, via published muscle + movement-keyword rules
  (`BIAS_RULES` exported). Medical conditions never bias — that would be advice — pinned by
  test. Stable partition, nothing hidden; each biased row states why and names the user's own
  onboarding note.
- **Per-table CSV archive** — one CSV per non-empty table, zipped (fflate, pure JS, round-trip
  tested), plus a README naming every table's row count so empty tables are stated, not silent.
  `u8ToBase64` hand-rolled (RN has neither Buffer nor btoa) and pinned against canonical
  encodings. Third export row in Settings.
