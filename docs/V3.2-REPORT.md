## Bugs found by taking screenshots, fixed and pinned

1. **Ledger hide-the-numbers fell through to the onboarding prompt**
   (`TodayScreen.tsx`): with numbers hidden and targets present, the hero
   card rendered "No daily targets yet — finish onboarding". Extracted the
   branch into `ledgerHeroMode()` in the screen model; pinned by three
   tests. Tiles already handled it correctly.
2. **Status-bar icons were hardcoded light** (`App.tsx`): invisible
   clock/battery on the two paper themes (Humanist, Brutalist). Icon style
   now derives from `relativeLuminance(theme.surfaces.bg)`; the
   themeConformance suite pins ≥4.5:1 icon contrast per theme.
3. **A failed core fetch impersonated an answer** (`appStore.ts`), two
   ways: a failed profile fetch still set `bootstrapped`, routing signed-in
   onboarded users into onboarding on cold starts with a slow/absent
   network (reproduced repeatedly on the emulator); and any transient
   failure clobbered known-good profile/targets with null, flashing "no
   daily targets yet" on token refreshes. Failure now keeps last-known-good,
   only a succeeded fetch is authoritative, and a retry is scheduled.
   Pinned by four store tests with mocked fetches.
4. **PPG bench torch request killed flash-less cameras**
   (`PpgDebugSheet.tsx`): `torch="on"` on a device without a flash stalls
   the capture session at 0 frames forever. Now conditional on
   `device.hasTorch`; the silent `require` catch also logs its error — it
   had hidden the real failure below for most of an afternoon.
5. **vision-camera 4.7.3 vs CameraX 1.6.0, rounds 2–3** (pnpm patch): the
   public-interop patch needed two more sites — `getMaxFieldOfView` (found
   at release compile) and `getDeviceTypes`, whose
   `cameraCharacteristicsMap` call compiles against vision-camera's own
   CameraX 1.5.0-alpha03 but NoSuchMethodErrors at runtime against the
   1.6.0 the app ships (the camera2-pipe rewrite removed it). The bench
   only reported "camera module isn't in this build", which is what makes
   fix #4's logging matter.

Also committed alongside: the babel transform/proposal plugins + preset-

pnpm isolation (worklets-core re-transforms worklet code with its own
preset list).

## Honest caveats

- The walkthrough shots were taken across two days of app time (WED 2 /
  THU 3 SEPT headers vary between sections; each shot is individually
  truthful). The six theme shots are same-day, same-data by construction.
- Macro/target numbers differ between some walkthrough shots because the
  target engine legitimately recomputed mid-capture ("WHY: profile
  updated — maintenance calories from estimated expenditure"). Every shot
  shows real values the app computed at that moment.
- `today-hidden` and `recover-ppg` were captured on the debug build (the
  bench is `__DEV__`-gated); everything else on the release build. No
  LogBox or dev chrome appears in any committed shot.
- The emulator quickboot snapshot rolled the installed APK back to Aug 28
  mid-batch and the guest wifi needed a manual associate after cold boot —
  both now documented in `screenshots.md` so the next run doesn't lose an
  hour to them.
